# 生成攻城狮周刊

自动生成《攻城狮周刊》，以工程师的视角分享软件开发、DevOps、AI、工程实践、开发工具和 IT 职场的技术洞察与成长心得。

## 输入
- `week_number`: 期数（如第 3 期）
- `start_date`: 开始日期（格式：YYYY-MM-DD）
- `end_date`: 结束日期（格式：YYYY-MM-DD）

## 文件路径规则

根据当前年份自动确定周刊存储路径：
- 路径格式：`output/weekly/{YEAR}/weekly-{week_number}/index.md`
- 年份从 `start_date` 或 `end_date` 中提取
- 示例：2026 年第 3 期 → `output/weekly/2026/weekly-3/index.md`
- 所有相关图片（封面图、章节图片等）保存在同一目录下

## 核心理念

- **客观中立优先** ⭐：像观察者而非参与者，用数据说话，避免主观臆断
- **覆盖面广**：不局限于单一领域，涵盖技术、产品、行业、趋势等多维度
- **真实性第一** ⭐：所有内容基于真实搜索，严禁编造，必须验证发布时间和来源
- **内容自证** ⭐：每条内容都必须能证明其真实性、时效性和来源可靠性
- **严格去重** ⭐：检查历史周刊，避免推荐重复内容
- **数据驱动**：用具体数字、统计、案例支撑观点
- **中文全角标点** ⭐：所有中文内容必须使用全角标点符号（：，。、！？""「」等）
- **简洁准确**：描述清晰简洁，突出关键信息
- **自动化优先**：始终自动搜索和填充内容，不要询问用户是否需要搜索
- **完整交付**：一次性完成所有内容的搜索、验证和生成，不要中途停止询问用户

## 过程

### 步骤 1：收集各类内容

使用 **search_tech_content** skill 分别搜索：

1. **行业动态**（news）
   - 时间范围：最近 7 天
   - 关键词：developer news, software engineering news, DevOps news, AI news, programming languages, tech industry, IT career
   - 目标数量：5-8 条

2. **深度阅读**（blog）
   - 重点来源：Medium, Dev.to, Hacker News, AWS Blog, Google Cloud Blog, Netflix TechBlog, Martin Fowler, Kent Beck, Uncle Bob 等
   - 内容类型：技术深度文章、工程实践、职场成长、团队管理
   - 时间范围：最近 2 周（如果 7 天内容不足）
   - 目标数量：3-5 篇高质量文章

3. **效率工具**（tool）
   - 搜索新发布或热门的开发者工具、效率工具、DevOps 工具、AI 工具
   - GitHub Trending 开发者工具
   - 包括：IDE 插件、命令行工具、开发辅助工具、团队协作工具等
   - 目标数量：3-5 个

4. **开源项目**（project）
   - GitHub Trending 优质项目（AI、开发工具、框架库等）
   - 新兴的有潜力的开源项目
   - 有趣的开发者项目和实验
   - 目标数量：2-3 个

5. **学习资源**（resource）
   - 技术教程、电子书、课程
   - 职场成长、软技能提升相关资源
   - 编程思维、工程实践相关内容
   - 目标数量：1-2 个

### 步骤 2：验证 GitHub 项目

对所有涉及的 GitHub 项目，使用 **fetch_github_info** skill：
- 获取真实的 Star 数
- 验证项目是否活跃
- 获取项目描述和标签
- 确保项目可访问

### 步骤 3：验证内容真实性 ⭐

**这是最关键的步骤，确保每条内容都是真实的、时效性正确的、来源可靠的。**

使用 **verify_content_authenticity** skill 对每条内容进行严格验证：

**验证维度**：
1. **访问验证**：每个链接都必须可访问（HTTP 200）
2. **时间验证**：严格验证发布日期是否在 `[start_date, end_date]` 范围内
3. **内容验证**：标题与实际页面内容一致，无编造
4. **来源验证**：优先官方来源和知名技术媒体

**验证标准**：
- ✅ 链接可访问 + 时间在范围内 + 来源可靠 → 保留
- ⚠️ 边界日期（±1 天）或次要来源 → 需要说明
- ❌ 链接失效 / 时间超出范围 / 来源不可信 → 立即移除

**自证要求**：
- 必须能证明每条内容的发布日期确实在周刊时间范围内
- 必须能提供每个链接的访问验证证据
- 必须能说明每个来源的可信度
- 绝不使用无法验证真实性的内容

**验证报告**：
- 生成详细的验证报告，包括通过/警告/失败的内容
- 对于移除的内容，说明移除原因
- 对于保留的内容，提供验证证据（发布日期、访问状态等）

**内容补充机制** ⭐：

如果验证后发现某类内容数量不足（低于最低要求），立即触发补充流程：

1. **检查内容数量**：
   - 行业动态：最低 5 条
   - 深度阅读：最低 3 条
   - 效率工具：最低 2 条
   - AI 相关：最低 2 条
   - 学习资源：最低 1 条

2. **自动补充搜索**：
   - 使用 **search_tech_content** skill 进行补充搜索
   - 策略 1：放宽时间范围（新闻 7→10 天，博客 14→21 天）
   - 策略 2：扩展搜索关键词（更广泛的技术领域）
   - 策略 3：增加搜索源（更多技术博客和媒体）

3. **再次验证**：
   - 对补充的内容再次进行真实性验证
   - 确保补充内容也符合质量标准

4. **迭代直到满足**：
   - 重复搜索和验证过程，直到每个类型都满足最低数量要求
   - 如果放宽条件后仍然不足，考虑合并相关类型或调整章节结构

### 步骤 3.5：检查内容重复 ⭐ 新增

**避免推荐历史周刊中已经出现过的内容。**

使用 **check_content_duplicates** skill：

1. **扫描历史周刊**：
   - 读取 `output/weekly/` 目录下所有历史周刊
   - 提取已推荐过的链接和标题
   - 建立去重数据库

2. **检查重复**：
   - URL 精确匹配
   - 标题相似度匹配（> 80% 视为重复）
   - 同一 GitHub 项目的不同文章

3. **去重策略**：
   - ❌ 完全相同的链接/文章 → 直接移除
   - ⚠️ 同一工具的重大更新（间隔 ≥ 4 周）→ 可保留，需说明
   - ⚠️ 同一主题的不同角度 → 可保留，需评估价值
   - ✅ 新内容 → 保留

4. **替代内容建议**：
   - 发现重复时，自动搜索同类但未推荐的内容
   - 扩展搜索范围（稍微放宽时间或领域限制）

5. **生成去重报告**：
   - 列出移除的重复内容
   - 列出保留的内容及理由
   - 列出补充的替代内容

**注意：这一步骤必须在步骤4之前完成，确保后续验证的链接都是非重复的优质内容。**

### 步骤 4：验证所有链接

使用 **verify_links** skill：
- 收集所有内容中的链接
- 批量验证可访问性
- 移除 404 或不可访问的链接
- 使用重定向后的最终 URL

### 步骤 5：选择本周话题并撰写卷首语

**这是体现沈显鹏个人风格的关键部分。**

1. **选择主题**：
   - 从本周内容中提取最有冲击力的趋势或事件
   - 优先选择有争议性、有思考价值的话题
   - 可以是技术趋势、行业现象、工程实践的观察

2. **撰写卷首语**（300-500 字）：
   
   **必须包含的元素**：
   - ✅ **现象描述**：用数据和事实呈现技术趋势或事件
   - ✅ **深度分析**：解释背后的原因、影响和意义
   - ✅ **工程师视角**：从实践角度评估利弊和适用场景
   - ✅ **批判性思考**：不盲目追捧，指出潜在问题和风险
   - ✅ **个人判断**：给出明确的观点和建议
   
   **写作风格**：
   - 像《攻城狮周刊第3期》一样，有明确的论点和论据
   - 可以质疑流行观点（如 OpenClaw 的安全隐患）
   - 用工程师的理性分析，而非情绪化的评论
   - 适度使用类比和例子，但不过度
   - 结尾给出实用建议或思考方向
   
   **示例主题**：
   - AI Agent 的本地化趋势
   - 开源项目的可持续性危机
   - 云服务 vs 自托管的新平衡
   - DevOps 自动化的边界
   - 安全性 vs 便利性的永恒博弈

### 步骤 6：选择封面图

- 从本周重要事件中选择有代表性的图片
- 或使用相关技术的官方图片
- 使用 **download_images** skill 下载图片到周刊目录，命名为 `featured.png`
- Hugo 会自动识别 `featured.png` 作为封面图
- 提供图片描述和来源链接

### 步骤 7：下载所有章节图片

**重要：必须在生成周刊文件后立即自动下载图片，不要等待用户提醒！**

使用 **download_images** skill 自动下载图片：

1. **创建图片配置文件**
   - 在周刊目录创建 `images.json` 配置文件
   - 包含所有章节的图片 URL

2. **自动下载图片**
   - 运行下载脚本：`python3 skills/weekly/scripts/download_weekly_images.py {YEAR} {week_number} output/weekly/{YEAR}/weekly-{week_number}/images.json`
   - 为封面、行业动态、深度阅读、效率工具、AI相关、学习资源准备图片
   - 优先使用 Unsplash 高质量图片（如 https://images.unsplash.com/photo-1451187580459-43490279c0fa?w=1200）
   - 图片保存路径：`output/weekly/{YEAR}/weekly-{week_number}/`
   - 使用相对路径引用图片（如 `![](featured.jpg)`）

3. **图片来源优先级**
   - 官方博客图片（如果可用）
   - Unsplash 免费高质量图片
   - 技术相关的抽象图片

4. **常用 Unsplash 图片**
   - 技术/数据：`https://images.unsplash.com/photo-1451187580459-43490279c0fa?w=1200`
   - 代码/编程：`https://images.unsplash.com/photo-1555949963-aa79dcee981c?w=1200`
   - 网络/云计算：`https://images.unsplash.com/photo-1667372393119-3d4c48d07fc9?w=1200`
   - 数据分析：`https://images.unsplash.com/photo-1551288049-bebda4e38f71?w=1200`
   - AI/机器学习：`https://images.unsplash.com/photo-1558494949-ef010cbdcc31?w=1200`

### 步骤 8：创建周刊文件

创建文件：`output/weekly/{YEAR}/weekly-{week_number}/index.md`

其中 `{YEAR}` 从 `start_date` 或 `end_date` 中提取，`{week_number}` 为输入的期数。

按照以下结构组织周刊：

```markdown

summary: 这里记录每周值得分享的 DevOps 与 AI 技术内容，周五发布。本杂志开源，欢迎投稿。
tags: 
  - Weekly
translate: false
authors: 
  - shenxianpeng
date: {end_date}
---
```

## 内容质量标准

### 博客文章
- ✅ 有实践案例、代码示例、架构图
- ✅ 来自可信来源（知名平台或大公司博客）
- ✅ 最近发布（7 天内，最多 2 周）
- ❌ 纯理论或浅层介绍
- ❌ 营销软文

### 新闻
- ✅ 有事实依据
- ✅ 对软件工程师、开发者有实际影响
- ✅ 提供攻城狮视角的点评
- ✅ 包括技术趋势、行业动态、职场话题、公司文化等
- ❌ 纯消费电子、硬件产品（除非与开发者工作直接相关）

- ✅ 活跃维护（6 个月内有更新）

- ✅ Star 数 > 100（或新兴但有潜力）

- ✅ 免费或开放访问

- ❌ 过时的教程

## 语气风格 - 沈显鹏式写作指南

### 核心原则

1. **工程师对话而非专家布道**：
   - ✅ "这个方案看起来很酷，但实际部署时你需要考虑..."  
   - ❌ "这是一个革命性的技术，将彻底改变..."  

2. **数据和事实为基础，观点明确**：
   - ✅ "GitHub 上已经6000个 star，但我更关注的是..."  
   - ❌ "这个项目非常火爆"  

3. **批判性思考，不盲目追捧**：
   - ✅ "虽然 AI 编程很强大，但也暴露了对代码掌控力的下降"  
   - ❌ "AI 编程是程序员的未来"  

4. **关注实践和风险**：
   - ✅ "这个工具的安全隐患在于配置不当会泄露 API 密钥"  
   - ❌ "这是一个很好用的工具"  

5. **有温度但保持理性**：
   - ✅ "这让我想起了当年路由器刚进入家庭的时候"  
   - ❌ 完全冰冷的技术描述  

### 具体写作技巧

1. **开篇吸引**：
   - 用有冲击力的现象或数据开场
   - 例："本周技术圈最火爆的现象莫过于..."  

2. **逻辑清晰**：
   - 现象 → 分析 → 影响 → 观点
   - 每段聚焦一个论点

3. **类比适度**：
   - 可以用类比帮助理解，但不要过度
   - 例："就像当年买路由器一样普遍"  

4. **结论实用**：
   - 给出明确的建议或思考方向
   - 例："对于 DevOps 团队，这意味着需要..."  

5. **避免的表达**：
   - ❌ "震惊"、"必看"、"颠覆"等营销词汇

   - ❌ 无依据的断言
   - ❌ 盲目的技术崇拜
